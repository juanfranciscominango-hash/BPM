Documentación Entra ID

Guía completa para la integración con Microsoft Entra ID

¿Qué es Entra ID?

Microsoft Entra ID (anteriormente Azure Active Directory) es el servicio de identidad y acceso basado en la nube de Microsoft. Proporciona autenticación y autorización para aplicaciones web y móviles.

Nota: Esta aplicación utiliza MSAL Browser v4 para la integración con Entra ID.
Configuración en Azure Portal

  1. Acceder al Azure Portal:

    Ve a portal.azure.com e inicia sesión.

  2. Buscar "App registrations":

    En la barra de búsqueda, escribe "App registrations" y selecciónalo.

  3. Crear nueva aplicación:

    Haz clic en "New registration" y completa los campos requeridos.

  4. Guardar Application ID:

    Copia el "Application (client) ID" que se genera.

Permisos de API
  1. En tu App Registration, ve a "API permissions"
  2. Haz clic en "Add a permission"
  3. Selecciona "Microsoft Graph"
  4. Agrega los siguientes permisos delegados:
    • User.Read - Leer perfil básico del usuario
    • User.ReadBasic.All - Leer perfiles básicos de todos los usuarios
    • Directory.Read.All - Leer datos del directorio (para roles)
  5. Haz clic en "Grant admin consent" para los permisos
Importante: Los permisos de directorio requieren consentimiento de administrador.

URLs de Redireccionamiento

Configura las siguientes URLs en "Authentication":

  • Desarrollo: http://localhost:4200
  • Producción: https://tu-dominio.com
  • Staging: https://staging.tu-dominio.com
Flujo de Concesión Implícita

Habilita "Access tokens" e "ID tokens" para aplicaciones SPA.

Configuración en el Proyecto Angular
Archivo environment.ts

Configura las variables de entorno en src/environments/environment.ts:

export const environment = {
  production: false,
  msalConfig: {
    auth: {
      clientId: 'TU_CLIENT_ID_AQUI',
      authority: 'https://login.microsoftonline.com/TU_TENANT_ID',
      redirectUri: 'http://localhost:4200'
    },
    cache: {
      cacheLocation: 'localStorage',
      storeAuthStateInCookie: false
    }
  },
  apiConfig: {
    scopes: ['user.read'],
    uri: 'https://graph.microsoft.com/v1.0/me'
  }
};
Archivo msal.config.ts

Configura MSAL en src/app/config/msal.config.ts:

import { Configuration } from '@azure/msal-browser';

export const msalConfig: Configuration = {
  auth: {
    clientId: environment.msalConfig.auth.clientId,
    authority: environment.msalConfig.auth.authority,
    redirectUri: environment.msalConfig.auth.redirectUri,
    postLogoutRedirectUri: environment.msalConfig.auth.redirectUri
  },
  cache: {
    cacheLocation: 'localStorage',
    storeAuthStateInCookie: false
  }
};

Ejemplos de Consumo de Servicios
API Service

Consumo de APIs REST con autenticación MSAL

import { HttpClient } from '@angular/common/http';
import { MsalService } from '@azure/msal-angular';

@Injectable({
  providedIn: 'root'
})
export class ApiService {
  constructor(
    private http: HttpClient,
    private msalService: MsalService
  ) {}

  async getData() {
    const token = await this.getAccessToken();
    return this.http.get('/api/data', {
      headers: { Authorization: `Bearer ${token}` }
    });
  }

  private async getAccessToken(): Promise<string> {
    const result = await this.msalService.acquireTokenSilent({
      scopes: ['api://tu-api-id/.default']
    });
    return result.accessToken;
  }
}
Redis Service

Cache distribuido con Redis y autenticación

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';

@Injectable({
  providedIn: 'root'
})
export class RedisService {
  constructor(private http: HttpClient) {}

  async getCachedData(key: string) {
    return this.http.get(`/api/cache/${key}`, {
      headers: { Authorization: `Bearer ${this.getToken()}` }
    });
  }

  async setCacheData(key: string, data: any) {
    return this.http.post(`/api/cache/${key}`, data, {
      headers: { Authorization: `Bearer ${this.getToken()}` }
    });
  }

  private getToken(): string {
    // Obtener token de MSAL
    return localStorage.getItem('msal.token') || '';
  }
}
WCF Service

Integración con servicios WCF legacy

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';

@Injectable({
  providedIn: 'root'
})
export class WcfService {
  constructor(private http: HttpClient) {}

  async callWcfMethod(data: any) {
    const soapEnvelope = this.createSoapEnvelope(data);
    return this.http.post('/wcf/Service.svc', soapEnvelope, {
      headers: {
        'Content-Type': 'text/xml',
        'SOAPAction': 'http://tempuri.org/IMyService/MyMethod',
        'Authorization': `Bearer ${this.getToken()}`
      },
      responseType: 'text'
    });
  }

  private createSoapEnvelope(data: any): string {
    return `<soap:Envelope>...</soap:Envelope>`;
  }

  private getToken(): string {
    return localStorage.getItem('msal.token') || '';
  }
}
Roles y Permisos
Obtener Roles del Usuario

Los roles se obtienen del token ID proporcionado por Entra ID.

Nota: Los roles se configuran en Azure AD y se incluyen automáticamente en el token ID.
Solución de Problemas

Error: "interaction_in_progress"

Solución: Limpiar el localStorage y reiniciar el navegador.

localStorage.clear();
Error: "invalid_client"

Solución: Verificar que el Client ID sea correcto en la configuración.

Error: "access_denied"

Solución: Verificar permisos y consentimiento de administrador en Azure AD.

Token Expirado

Solución: MSAL automáticamente renueva tokens expirados.

Token no Contiene Roles

Solución: Verificar que los roles estén asignados en Azure AD.

Configuración de CORS en Desarrollo

Para desarrollo local, configurar el proxy en angular.json.
