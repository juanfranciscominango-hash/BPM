Guía completa para consumir APIs en este proyecto

🎯 Arquitectura de Consumo de APIs

Este proyecto implementa una arquitectura moderna de consumo de APIs basada en HttpClient de Angular con un API Gateway CORS proxy que centraliza todas las comunicaciones HTTP. Esta arquitectura permite autenticación segura, manejo de certificados auto-firmados y logging detallado.

✨ Características Principales:
  • ✅ HttpClient para peticiones HTTP (estándar de Angular)
  • ✅ API Gateway en 172.20.70.56:3000 (CORS proxy)
  • ✅ Autenticación Bearer token-based
  • ✅ Auditoría con IP y GUID únicos
  • ✅ Logging detallado de peticiones/respuestas
  • ✅ Interceptores HTTP para manejo centralizado
📊 Stack Tecnológico:
  • 🔹 Frontend: Angular 20 + HttpClient + RxJS
  • 🔹 Gateway: Node.js + Express
  • 🔹 Autenticación: APIs InnovaConsulting (APIM)
  • 🔹 Transporte: HTTPS (con interceptores)
  • 🔹 Base de datos: Redis (caché)
Flujo Típico: Angular → Gateway (localhost:3000) → API Externa (InnovaConsulting) → Gateway → Angular
⚙️ Configuración del API Gateway
🔧 ¿Qué es el API Gateway?

El API Gateway es un servidor Node.js/Express que actúa como proxy centralizado para todas las peticiones HTTP. Está diseñado para:

  • 🔀 Enrutar peticiones desde Angular hacia APIs externas (InnovaConsulting)
  • 🔒 Manejar CORS y certificados auto-firmados
  • 📝 Registrar logs detallados de peticiones y respuestas
  • 🔄 Propagar headers de autenticación (Authorization Bearer)
  • ⏱️ Controlar timeouts y errores de conexión

Toda petición que requiera acceso a APIs protegidas debe primero obtener un token de sesión. Este token se genera contactando a la API de InnovaConsulting:

Endpoint: https://apis-test.bgr.com.ec/api/acceso/servicios/solicitar

Método: POST

Credenciales requeridas: NameAplication + ApiKeySistema

Respuesta: Token en respuestaToken.tokenSesion

📋 Paso 2: Usar Token en Petición Protegida

Con el token obtenido, se pueden hacer peticiones a APIs protegidas incluyendo el header Authorization: Bearer [TOKEN]:

Header requerido:

try {

Recomendación: Siempre envuelve las peticiones en try/catch para manejar errores de conexión.

⏱️ Secuencia de Pasos

¿Qué hace? Se contacta con InnovaConsulting para obtener un token de sesión válido.

Tiempo promedio: 1-2 segundos

// Se envía la solicitud de token
URL: https://apis-test.bgr.com.ec/api/acceso/servicios/solicitar
Body: { auditoria, datosIniciarSesion }

// Se recibe el token
Respuesta: { respuesta, respuestaToken }
Token extraído de: respuestaToken.tokenSesion

¿Qué hace? El componente guarda el token obtenido en una variable.

this.tokenSesionCatalogos = respuestaToken.tokenSesion;
console.log('✅ Token guardado:', this.tokenSesionCatalogos);

¿Qué hace? Se prepara la petición con los datos + token en headers.

const proxyBody = {
  url: 'https://apis-test.bgr.com.ec/api/instituciones/catalogo/v1/consultar',
  method: 'POST',
  data: { auditoria, datosCanal },
  headers: {
    'Authorization': `Bearer ${this.tokenSesionCatalogos}`
  }
};

¿Qué hace? Axios envía la petición al Gateway en localhost:3000.

const response = await this.axiosInstance.post(
  'http://localhost:3000/proxy/request',
  proxyBody
);

¿Qué hace? El Gateway recibe la petición, valida, loguea y reenvía a InnovaConsulting.

// Gateway recibe POST /proxy/request
// Extrae: url, method, data, headers
// Reenvía a: https://apis-test.bgr.com.ec/api/...
// Con headers: Authorization: Bearer [TOKEN]
// Loguea: URL destino, método, datos, respuesta

¿Qué hace? El componente recibe y procesa los datos del catálogo.

this.catalogosData = response.data.data || response.data;
console.log('✅ Catálogos obtenidos:', this.catalogosData);
Nota: Este flujo se ejecuta automáticamente cuando haces clic en los botones de prueba abajo.

API Service

Consumo de APIs REST con interceptores HTTP

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

@Injectable({
  providedIn: 'root'
})
export class ApiService {
  constructor(private http: HttpClient) {}

  getUsers(): Observable<User[]> {
    return this.http.get<User[]>('/api/users');
  }

  createUser(user: User): Observable<User> {
    return this.http.post<User>('/api/users', user);
  }

  updateUser(id: string, user: User): Observable<User> {
    return this.http.put<User>(`/api/users/${id}`, user);
  }

  deleteUser(id: string): Observable<void> {
    return this.http.delete<void>(`/api/users/${id}`);
  }
}

Servicio de Autenticación

Ejemplo de servicio para consumir la API de autenticación:

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';
import { environment } from '../../../environments/environment';

@Injectable({
  providedIn: 'root'
})
export class AuthApiService {
  private baseUrl = (environment as any).CentralizadaMs.configApiUrl;

  constructor(private http: HttpClient) {}

  solicitarAutorizacion(): Observable<any> {
    const url = this.baseUrl + (environment as any).CentralizadaMs.SolicitarAutorizacion;

    const body = {
      auditoria: {
        ipCliente: 'ObtenerIPCliente',
        aplicacion: 'PlantillaAngular'
      },
      datosIniciarSesion: {
        nombreAplicacion: (environment as any).CentralizadaMs.NameAplication,
        apiKeySistema: (environment as any).CentralizadaMs.ApiKeySistema
      }
    };

    return this.http.post(url, body);
  }

  obtenerConfiguracionesAplicacion(): Observable<any> {
    const url = this.baseUrl + (environment as any).CentralizadaMs.ObtenerConfiguracionesAplicacion;

    const body = {
      nombreAplicacion: (environment as any).CentralizadaMs.NameAplication,
      apiKeySistema: (environment as any).CentralizadaMs.ApiKeySistema
    };

    return this.http.post(url, body);
  }
}
