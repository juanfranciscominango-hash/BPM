Documentación Angular

Guía completa para trabajar con Angular en este proyecto

Introducción

Esta documentación proporciona una guía completa para trabajar con Angular en el proyecto PlantillaAngularBootstrap. Aquí encontrarás información sobre configuración, versiones, mejores prácticas y soluciones a problemas comunes.

Nota: Este proyecto utiliza Angular 20 con arquitectura de componentes standalone.
Versiones y Requisitos
Versiones Principales
  • Angular CLI 20.x
  • Angular Core 20.x
  • Node.js 18.x+
  • npm 9.x+
Dependencias Clave
  • MSAL Browser 4.x
  • Bootstrap 5.x
  • RxJS 7.x
  • TypeScript 5.x
Configuración Básica del Proyecto

1. Clonar el repositorio
git clone <url-del-repositorio>
cd PlantillaAngularBootstrap
2. Instalar dependencias
npm install
3. Configurar variables de entorno

Copiar y configurar el archivo environment.ts:

cp src/environments/environment.example.ts src/environments/environment.ts
4. Ejecutar el proyecto
npm start

Este proyecto utiliza componentes standalone de Angular 20:

  • Standalone Components: Componentes independientes sin módulos
  • Control Flow Syntax: Uso de directivas de control de flujo modernas
  • Signals: Para manejo reactivo de estado
  • Inject Function: Para inyección de dependencias
Características principales:
  • Componentes independientes sin necesidad de módulos NgModule
  • Imports directos en el decorador del componente
  • Sintaxis de control de flujo mejorada
  • Inyección de dependencias con la función inject()
Problemas Comunes y Soluciones

Problema: "Cannot find module" o "Module not found"

Solución:

rm -rf node_modules package-lock.json
npm install
Problema: Errores de TypeScript en componentes standalone

Solución: Asegurarse de que todos los imports necesarios estén incluidos en el array imports del componente.

Problema: "ExpressionChangedAfterItHasBeenCheckedError"

Solución: Usar ChangeDetectorRef o cambiar la detección de cambios a OnPush.

Problema: Problemas con MSAL

Solución: Verificar configuración en environment.ts y permisos en Azure AD.

Optimización: Lazy Loading

Usar carga diferida para rutas grandes mejora el rendimiento inicial de la aplicación.

Optimización: OnPush Change Detection

Usar ChangeDetectionStrategy.OnPush en componentes que no cambian frecuentemente.

Ejemplos de Consumo de Servicios

Ejemplos prácticos de cómo consumir los diferentes servicios disponibles en la arquitectura modular.

API REST 
// Inyección del servicio
private apiService = inject(ApiService);

// Ejemplo de GET
async loadUsers() {
  const result = await this.apiService.get('/users');
  if (result.success) {
    this.users = result.data;
  }
}

// Ejemplo de POST
async createUser(userData: any) {
  const result = await this.apiService.post('/users', userData);
  return result.success;
}
Redis 
// Inyección del servicio
private redisService = inject(RedisService);

// Ejemplo de operaciones
async cacheUserData(userId: string, data: any) {
  // Guardar en Redis con expiración
  const result = await this.redisService.set(
    `user:${userId}`,
    JSON.stringify(data),
    3600 // 1 hora
  );
  return result.success;
}

// Recuperar datos
async getUserData(userId: string) {
  const result = await this.redisService.get(`user:${userId}`);
  return result.success ? JSON.parse(result.data) : null;
}
WCF/SOAP 
// Inyección del servicio
private wcfService = inject(WcfService);

// Ejemplo de llamada SOAP
async getClientData(clientId: number) {
  const result = await this.wcfService.callMethod(
    'ObtenerDatosCliente',
    { idCliente: clientId }
  );

  if (result.success) {
    return result.data;
  }
  throw new Error(result.error);
}

// Con parámetros complejos
async processOrder(orderData: any) {
  return await this.wcfService.executeOperation(
    'ProcesarPedido',
    orderData,
    { soapAction: 'http://tempuri.org/IOrderService/ProcessOrder' }
  );
}
Nota: Todos los servicios incluyen manejo automático de errores, timeouts configurables y logging detallado. Consulta la documentación de cada módulo para más opciones de configuración.
